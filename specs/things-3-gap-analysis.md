# Things 3 vs Hmart Kanban - Gap Analysis

Generated 2026-05-19. Source-of-truth audit of every notable Cultured Code Things 3 feature, mapped against the current Hmart Kanban implementation (Vue 3 + Supabase, `~/Documents/hmart/hmart-kanban`). Things 3 facts verified against Cultured Code's official support docs (culturedcode.com/things/support, culturedcode.com/things/features), the keyboard-shortcut reference, the URL scheme reference, and Cultured Code's blog. Hmart facts read directly from the codebase as of this date.

## TLDR

Hmart Kanban already has the bones of Things 3: areas, projects, todos, checklists, tags, repeating rules, the four state lists (Today, Anytime, Upcoming, Someday, Logbook), an Inbox, a kanban view, drag-and-drop reorder, optimistic CRUD with undo, a command palette on Cmd+K, persistent filters, and a Claude-augmented capture pipeline that Things 3 has no equivalent for. The database schema (`0001_hmart_init.sql`) is in many ways more ambitious than Things' own: headings, repeating rules, captures, picker_runs, and seven specialty reservoirs (network, apply, learn, make, write, outings, share) are already modeled and migrated. What's missing is mostly **at the input layer and the editing surface** - the small daily gestures that make Things feel weightless. The headings table exists in SQL but no UI references it; reminders/alarms have no column, no UI, and no notification path; deadlines and start dates are stored but the When picker that mediates them in Things ("Today, This Evening, Tomorrow, This Weekend, custom, Someday" in one popover) is absent; natural-language date parsing is absent; multi-select with bulk move/schedule is absent; calendar event integration is absent; project completion ceremony (the pie fill, the "all done?" prompt, the project state transition to `completed`) is partial - the column exists, no UI surfaces it. Keyboard shortcuts cover Cmd+K only; Things 3 ships ~80 mapped shortcuts and Hmart's lone capture hotkey is the bare letter `c`. The Magic Plus button - the single most ergonomic creation gesture in Things - is entirely absent: Hmart has a FAB that does one thing (open the capture sheet) where Things' Magic Plus is a five-way directional gesture (drop on Inbox / drop in list / drop under heading / drop on left margin to create heading / drop on area to create project). Halim should expect that the bulk of the daily-use deltas live in three places: `TodoEditor.vue` (date pickers, reminder, repeat upgrades, multi-select), `AddTaskInput.vue` (natural-language parse, magic-plus modal, syntax extensions), and one new file (`WhenPicker.vue`) that replaces today's two raw `<input type="date">` controls. The Tier A list below is twelve items and almost all of them are small surgical patches. Tier B is twelve more. Tier C captures the long-tail power features Things has and Hmart could match someday. Tier D explicitly accepts the things Hmart will never do, because Supabase + Claude replaces them or because they don't fit a cloud-resident model.

## Cross-cutting observations not in any single feature

1. **Empty states.** Hmart's `"nothing queued. take the morning."` (`Today.vue:94`) and `"inbox zero. nothing to triage."` (`Inbox.vue:262-264`) are charming. Things' empty states are similarly small. No gap here, just worth keeping the bar.
2. **Animations.** Things uses ~150ms easing on every interaction. Hmart's Sortable.js uses 150ms (`AreasNav.vue:120`, `ProjectKanban.vue`). Consistent. The TodoEditor expand/collapse could use a `<Transition>` wrapper to match.
3. **The Inbox is differently shaped than Things'.** Hmart's Inbox has a Claude-augmented capture pipeline (`captures` table with `pending / routing / needs_review / failed / routed` states) which Things has no equivalent for. This is a feature, not a gap, and worth preserving.
4. **The kanban view is something Things does not have.** `ProjectKanban.vue` is Hmart-original and is on purpose - it's the namesake of the app. Don't backport Things' lack-of-kanban.
5. **The Memory view (`Memory.vue`) is also Hmart-original.** Surfaces `memory_entries` (user rules, project rules, feedback, references, style guides) that Claude reads on every Picker run. Things has nothing like it. Keep it.
6. **The Areas/Projects sidebar drag-drop** (`AreasNav.vue:113-159`) is parity with Things. The cross-area drop is something Things does too. Verified working in code.
7. **Right-click context menus are entirely absent from Hmart.** Things relies heavily on them (Ctrl+click → "Remove from Project", "Convert to Project", "Repeat", "Delete"). Adding a `ContextMenu.vue` mounted via Teleport that takes a `{x, y, items}` payload is a one-afternoon job and unlocks at least four Tier-A/B items above (cancel, convert, move-to, show-in-project).

## Recommended sequencing (not asked for but useful)

Sprint 1 (one week, daily-use): WhenPicker + natural-language parse + reminders schema + magic-plus button + selection store + Cmd+T/E/R/O/S keyboard shortcuts. That single sprint closes seven of the twelve Tier-A items and would make Hmart feel like Things to use.

Sprint 2 (one week, structure): headings UI + project completion ceremony + bulk move dialog + drag-and-drop in list views. Closes another four Tier-A items and three Tier-B.

Sprint 3 (calendar + reminders fire-out): CalendarBar with Google Calendar OAuth + the `fire_reminders` Edge Function + service-worker push. Closes the last Tier-A item and unblocks daily use without leaving the app.

Anything beyond Sprint 3 is Tier B/C and can wait until the daily-use gaps stop biting.
